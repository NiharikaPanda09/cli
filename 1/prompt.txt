## 🔴 Part 2: The Technical Workflow Version

Here is the technical breakdown of the architecture, data pipeline, and execution workflow you are building for the CLI.

### 1. Architectural Overview
You are building a **Cobra-based CLI command** (`entire handoff`) in a fork of `entireio/cli`.

To ensure modularity (and protect against the "Noon Curveball"), the architecture uses the **Strategy Pattern**. Instead of monolithic parsing logic, you define a `handoff.Packet` struct and an `Extractor` interface. Different components (Intent, Dead-Ends, Curveball response) act as independent extractors that mutate the `Packet` concurrently or sequentially.

### 2. The Execution Workflow (Runtime)
When a user (or agent) executes `entire handoff --json`, the following execution flow occurs:

1. **CLI Bootstrap (`cmd/entire/cli/handoff.go`):**
   * The Cobra command parses flags (`--session`, `--json`, `--checkpoint`).
   * It initializes the storage backend by calling `checkpoint.Open(...)`, which returns an `api/checkpoint.PersistentStore` interface.
2. **State Resolution:**
   * The store resolves the requested session/checkpoint ID.
   * It calls `ReadSessionMetadataAndPrompts()` and `ReadSessionContent()` to load the raw blob data from the `.git/refs/entire/checkpoints/` namespace.
3. **The Extractor Pipeline (`packet.go`):**
   * An empty `handoff.Packet` struct is initialized.
   * The command iterates through a slice of registered `Extractor` interfaces (e.g., `IntentExtractor`, `DeadEndMiner`).
   * Each extractor receives the `Context` and the raw session state, executing its isolated logic to populate specific fields in the `Packet`.
4. **Serialization & Stdout:**
   * Based on the `--json` flag, the populated `Packet` is marshaled into a strict, machine-readable JSON schema (resolving issue `#1125`) and dumped to `stdout` for the new agent LLM to ingest.

### 3. The Data Pipeline (The "Dead-End Miner")
This is the core technical complexity of the project.
* **The Constraint:** You cannot use the existing `compact.BuildCondensedEntries` function because it internally discards the `result.status` field when creating the `CondensedEntry` struct. If you touch the `compact` package, you risk breaking 7 other upstream agent sniffers.
* **The Implementation:** Your `DeadEndMiner` extractor reads the raw `transcript.jsonl` bytes directly from the persistent store.
* It parses the v1 JSONL shape (`{v, agent, cli_version, type, ts, id, content[]}`) directly into a custom struct.

### 4. The Databricks Subsystem (Global State)
